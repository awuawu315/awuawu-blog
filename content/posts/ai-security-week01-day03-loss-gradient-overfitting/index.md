## 第一单元：损失函数到底在优化什么

-   损失函数决定检测模型如何学习；
-   分类阈值决定风险概率如何转化为类别；

### 1. 预测误差、单样本损失与整体损失

损失函数的作用不是简单判断“预测对还是错”，而是把预测结果与真实标签之间的差异转换为一个**可计算、可比较、可求导的数值**。

| 概念 | 含义 | 典型形式 |
| --- | --- | --- |
| 预测误差 | 预测与真实值之间的直接差异 | $y-\hat y$ |
| 单样本损失 | 一个样本对优化目标的贡献 | $L(\hat y_i,y_i)$ |
| 批次损失 | 当前一个批次样本的平均损失 | $\frac{1}{B}\sum \ell_i$ |
| 训练损失 | 一个训练轮次或整个训练集的平均损失 | $\frac{1}{N}\sum \ell_i$ |

### 2. 回归任务：均方误差

$$
\operatorname{MSE} = \frac{1}{N} \sum_{i=1}^{N} (y_i-\hat y_i)^2
$$

MSE 的主要特征是：**误差越大，惩罚增长越快。**

即对较大的预测偏差施以更强的惩罚。

### 3. 二元交叉熵

简称BCE，它是二分类中最常用的损失函数之一。

$$
L_{\text{BCE}} = -\left[ y\log(\hat p) + (1-y)\log(1-\hat p) \right]
$$

这个公式看起来包含两个部分，但对一个具体样本而言，实际上只会保留其中一部分。

主要特征：对“高度自信的错误预测”惩罚很大

模型给真实类别分配的概率越高，损失越小；给错误类别分配的概率越高，损失越大。

### 4. 用于梯度优化的损失函数通常需要可导

对依赖梯度的训练方法，损失函数不仅需要能够评价模型，还需要为参数更新提供可导或几乎处处可导的优化信号。

### 5.类别权重：改变模型“学习时更重视哪类错误”

方法：加权二元交叉熵

$L_{\text{BCE}} = -\left[w_+ y\log(\hat p) + (1-y)\log(1-\hat p) \right]$

$w_+$是正类权重，意思是在参数更新时，该样本对梯度更新的影响更大，用于调节样本不平衡对模型优化造成的影响。一般情况下，$w_+$的起点取值为负样本个数/正样本个数，取值最终取决于验证集上比较出来的数值。

```python
pos_weight = torch.tensor([9.0], dtype=torch.float32)

criterion = torch.nn.BCEWithLogitsLoss(
    pos_weight=pos_weight
)
```

### 6. 阈值调节：改变“多大概率才判定为攻击”

阈值：区分模型最终训练结果的数值

训练集→训练模型验证集→选择类别权重、超参数和阈值

验证集→选择类别权重、超参数和阈值测试集→只进行一次最终评价

测试集→只进行一次最终评价

### 7. Precision 和 Recall 是什么

Precision：精确率

—— 模型判定为攻击的样本中，有多少确实是攻击。

Recall：召回率

—— 所有真实攻击中，模型识别出了多少。

PR-AUC 是 Precision-Recall Area Under the Curve，即：精确率—召回率曲线下面积

**问题：**

1.  真实标签为攻击类 y=1。模型 A 输出攻击概率 0.9，模型 B 输出攻击概率 0.6。两者在阈值 0.5 下都预测正确，为什么模型 A 的 BCE 损失更小？
2.  为什么不适合直接使用准确率作为神经网络的训练损失？
3.  一个安全检测模型在训练集上的损失非常低，是否能够据此判断它对新型 Prompt Injection 也具有良好检测能力？说明原因。

我的回答：

1.  BCE 是模型预测正确的概率的越高，损失越小
    模型分配给**真实类别**的概率
2.  损失函数不仅需要评价模型模型，还要为模型训练提供可优化的、连续的信号。准确率不能作为训练损失，因为阈值分类通常是不连续的，训练算法无法从准确率中获得细粒度的参数优化方向。
3.  不能，损失非常低只说明模型对数据的拟合效果比较好，不能证明其有很好的泛化效果
    训练损失低只说明模型对训练数据的经验风险较低；是否具有泛化能力，需要观察独立验证集和测试集，尤其是分布变化、新型攻击表达和时间外样本上的表现。

## 第二单元：梯度下降——模型参数如何真正改变

梯度负责回答“往哪个方向改”，学习率负责回答“每次改多大”，优化器则实际执行参数更新。

### 梯度

1.  梯度是参数发生微小变化时，损失变化的方向和速度。
2.  梯度描述的是损失相对于参数的局部变化趋势。

### 学习率

1.  学习率是指参数每次更新的步骤，损失下降的幅度

### 批量梯度下降、小批量梯度下降与随机梯度下降

1.  批量梯度下降：使用全部数据进行梯度计算
2.  随机梯度下降：使用随机一个样本进行参数更新
3.  小批量梯度下降：每次使用一小批样本进行计算

### Epoch、Batch 与 Step

Batch：一次送入模型的一组样本，小批量梯度下降。

Step / Iteration：完成一次：前向传播→损失计算→反向传播→参数更新

Epoch：模型完整遍历一次训练集。

### 优化器

优化器就是在梯度下降这一优化思想上，定义具体更新规则。

Momentum——加入历史更新方向，使参数在方向一致时加速，并减少局部振荡。

Adam——根据梯度的一阶矩和二阶矩自适应调整不同参数的实际步长。

AdamW——将权重衰减从 Adam 的梯度更新中更合理地分离，Transformer 等模型中非常常见。

在参数更新过程中，梯度下降只知道怎么降低模型的损失，并不知道什么是真正训练完成，所以优化完成不等于目标实现。

在 PyTorch 中，一次参数更新通常包含以下步骤：

```python
optimizer.zero_grad()
logits = model(features)
loss = criterion(logits, labels)
loss.backward() # 只负责计算梯度
optimizer.step()  # 真正修改参数
```

对应关系如下：

| 代码 | 含义 |
| --- | --- |
| `zero_grad()` | 清除上一次计算留下的梯度 |
| `model(features)` | 前向传播，产生预测 |
| `criterion(...)` | 计算损失 |
| `loss.backward()` | 反向传播，计算各参数梯度 |
| `optimizer.step()` | 根据梯度和学习率更新参数 |

### 前向传播、反向传播

前向传播，指数据从模型输入端进入，经过各层计算，最终得到预测结果和损失的过程。

反向传播，指从损失函数开始，沿着前向计算过程反方向，计算每个参数对损失的影响。

**前向传播负责计算预测和损失，反向传播负责计算梯度，优化器负责更新参数**

### 欠拟合、过拟合

| 状态 | 训练集表现 | 验证集表现 | 核心问题 |
| --- | --- | --- | --- |
| 欠拟合 | 差 | 差 | 基本规律没有学会 |
| 合理拟合 | 较好 | 较好 | 学到可泛化规律 |
| 过拟合 | 很好 | 较差 | 记住训练集细节和噪声 |

欠拟合就是模型能力不足，或者训练不足

过拟合是模型在训练时不仅记住了规律，也学习到了训练集中的偶然相关性和噪声等，无法适应新数据集。
特征：验证集损失上升

问题：

1.  在 PyTorch 训练过程中，`loss.backward()` 和 `optimizer.step()` 分别完成什么工作？
2.  为什么参数更新公式中要沿梯度的反方向更新，而不是沿梯度方向更新？
3.  假设训练集有 1200 个样本，`batch_size=100`，训练 20 个 Epoch。每个 Epoch 有多少个 Step？整个训练过程中一共有多少次参数更新？
4.  某模型的训练损失持续下降，但验证损失先下降后持续上升。这个现象更可能说明什么？为什么不能仅根据训练损失判断模型是否训练得好？

回答：

1.  loss.backward()梯度计算，optimizer.step()参数更新
2.  梯度是指参数上升最快的方向，因此要沿着梯度反方向进行更新
3.  12个，240次参数更新
4.  模型过拟合，即模型不仅学习到了规律，还学习到了训练集的噪声和偶然性特征。
    训练损失只能说明模型是否是最优拟合，模型训练的好不好还要看在测试集上的效果以及泛化能力。
    训练损失只能反映**模型对训练数据的拟合程度**。模型是否训练良好，还要观察独立验证集上的损失和指标，并在模型配置冻结后，通过测试集评价最终泛化性能。

## 第三单元：泛化、正则化与过拟合控制

**正则化不是让训练集表现最好，而是缩小训练与未知数据之间的泛化差距**

### 1.泛化

泛化是指模型在未参与训练的新数据上的表现，即从有限训练样本中学习到可迁移的规律

### 2.过拟合原因

1.  模型复杂度相对数据规模过高

例如只有 500 条样本，却使用参数量较大的神经网络，模型有足够能力记住每条训练样本，而不必学习稳定规律

2.  训练时间过长

模型训练早期学习主要规律，后期可能开始适应噪声。因此训练轮次不是越多越好。

3.  特征中存在偶然相关性

-   某个用户只出现在攻击样本中；
-   某个工具名称只出现在正类；
-   攻击样本均由同一个模板生成；
-   正类和负类来自不同时间段或数据源。

模型会优先利用这些容易学习的捷径，英文常称为 **Shortcut Learning，捷径学习**。

4.  训练数据不足或多样性不足

攻击形式单一时，模型难以学习攻击类别的真实变化范围。

5.  标签噪声

部分正常样本被错误标为攻击，或攻击样本被标为正常。复杂模型可能逐步记住这些错误标签。

### 3.L2正则化

$L_{\text{total}} = L_{\text{data}} + \lambda\sum_j w_j^2$

基本思想是在损失中加入参数大小惩罚，不仅要求预测的误差小，也避免模型依赖特别大的参数。

L2 正则化会惩罚过大的权重，促使模型综合利用更多特征，而不是过度依赖单一特征。但这只是一种倾向，不代表 L2 一定能够消除错误相关性。

当 λ=0 时，相当于不使用 L2 正则化。

当 λ 较小时，可以轻度限制模型复杂度。

当 λ 过大时，模型参数被压得过小，可能无法学习有效规律，导致欠拟合。

### 4.L1正则化

L1 正则化加入的是参数绝对值：

$$
L_{\text{total}} = L_{\text{data}} + \lambda\sum_j|w_j|
$$

它与 L2 的主要区别是，L1 更容易把部分权重压到接近 0。

因此 L1 常被理解为可以产生更稀疏的参数或实现某种特征选择效果。

| 方法 | 惩罚对象 | 典型效果 |
| --- | --- | --- |
| L1 | 权重绝对值 | 更容易产生稀疏权重 |
| L2 | 权重平方 | 平滑压缩大权重 |
| Weight Decay | 优化阶段衰减权重 | 深度学习中常用 |

### 5.早停机制

早停机制会保存验证性能最好的模型，避免训练轮数过多造成过拟合

patience：容忍轮数，即连续多少轮损失没有改善就停止训练

早停依据验证集，不依据测试集。

### 6.Dropout

是常见的正则化方法，会随机将一组神经元设为0， 模型不能始终依赖固定的一组神经元或特征，必须学习更分散和稳健的表示。

即对模型施加随机扰动，避免某条固定路径长期主导预测的可能性

Dropout 只应在训练阶段启用。

```python
model.eval()

with torch.no_grad():
    logits = model(features)
```

其中：

-   `model.eval()`：切换 Dropout、BatchNorm 等模块的行为；
-   `torch.no_grad()`：不构建梯度计算图，减少内存和计算开销。

### 7.数据增强

在**不改变样本真实标签的前提**下，对**已有训练样本**进行**合理变换**，生成更多具有差异但语义一致的训练样本，从而**提高数据多样性**，减少模型记忆固定模板的倾向。即**保持标签不变，改变样本表现形式，增加训练数据多样性**。

数据增强主要发生在**训练数据准备阶段**。

什么情况下使用：

1.  训练数据较少
2.  类别不平衡
3.  部署环境存在已知变化
4.  模型明显依赖固定模板
5.  希望提高鲁棒性

| 方法 | 主要机制 | 使用阶段 | 过强时的风险 |
| --- | --- | --- | --- |
| L1 | 惩罚权重绝对值 | 训练 | 欠拟合、有效特征被压制 |
| L2/Weight Decay | 抑制大权重 | 训练 | 模型表达能力不足 |
| Dropout | 随机丢弃内部表示 | 训练 | 训练困难、欠拟合 |
| Early Stopping | 保存最佳验证轮次 | 训练控制 | 过早停止 |
| 数据增强 | 增加有效多样性 | 数据阶段 | 语义或标签被破坏 |
| 降低模型复杂度 | 限制模型容量 | 建模阶段 | 无法学习复杂规律 |

问题：

1.  加入 Weight Decay 后，训练损失略有升高，但验证损失明显下降。这是否说明模型变差了？为什么？
2.  `model.eval()` 和 `torch.no_grad()` 的作用分别是什么？两者能否互相替代？
3.  训练一个 Prompt Injection 检测模型时，把已有的 100 条攻击样本各复制 20 次，能否视为有效的数据增强？说明原因。
4.  为什么不能在测试集上选择 Early Stopping 的最佳 Epoch？

回答：

1.  不是模型变差了，说明正则化减少了模型对训练集噪声和偶然模式的拟合，**泛化能力有所改善
    ****Weight Decay 限制了模型参数过度增大，使模型不再一味追求最低训练损失。虽然训练集拟合略弱，但验证集表现改善，说明模型更可能学到了稳定规律。**
2.  model.eval() 会切换 dropout 等模块的丢弃行为，torch.no_grad() 不构建梯度计算图，减少内存开销，不能互相替代
3.  不能，简单的复制并没有增加数据集中的有效信息，没有增加数据多样性
4.  早停机制是为了保存验证模型效果最优时的参数，避免模型学习到训练集中的固定范式，从而造成过拟合。应该在验证集上选择早停的最佳 Epoch，如果在测试集上选择，会导致模型逐渐适应测试集，失去独立评估的效果

## 实验：观察欠拟合、过拟合与正则化

我们需要回答三个问题：

1.  小模型或训练不足时，是否会出现训练集和验证集都表现较差的欠拟合？
2.  大模型持续训练时，是否会出现训练损失下降、验证损失反而上升的过拟合？
3.  加入正则化和早停后，能否缩小训练集与验证集之间的差距？

### 实验设置

| 组别 | 模型容量 | Dropout | Weight Decay | Early Stopping | 观察目的 |
| --- | --- | --- | --- | --- | --- |
| UNDERFIT-欠拟合 | 很小 | 0 | 0 | 否 | 观察模型能力不足 |
| OVERFIT-过拟合 | 较大 | 0 | 0 | 否 | 观察持续训练后的过拟合 |
| REGULARIZED-正常 | 同上 | 0.35 | $10^{-3}$ | 是 | 观察泛化改善 |

### 代码中的训练循环

```python
optimizer.zero_grad()   # 清除旧梯度
logits = model(features)  # 前向传播
loss = criterion(logits, labels)  # 计算损失
loss.backward()    # 反向传播
optimizer.step()   # 参数更新
```

### 代码

1.  生成并划分数据
2.  定义二分类神经网络
3.  配置欠拟合、过拟合、正则化三组实验
4.  按 Batch 训练模型
5.  每个 Epoch 在训练集和验证集上评估
6.  根据验证损失早停，最后在测试集上评价

```text
ExperimentConfig(
    name="REGULARIZED",
    hidden_dims=(128, 128, 64),
    dropout=0.35,
    weight_decay=1e-3,
    learning_rate=1e-3,
    max_epochs=240,
    patience=20,
)
```

实验名称：REGULARIZED

隐藏层：128 → 128 → 64

Dropout：0.35

权重衰减：0.001

学习率：0.001

最大训练轮数：240

早停容忍轮数：20

问题：

1.  `UNDERFIT` 组的 Train–Val Loss Gap 只有 0.0165，比另外两组都小。为什么不能因此认为它是最好的模型？
2.  `OVERFIT` 组的最佳验证 Epoch 是 10，但最终训练到了 240。Epoch 10 之后发生了什么？
3.  为什么 `REGULARIZED` 曲线的最后一个验证损失约为 0.46，而实验汇总中的最终 Validation Loss 是 0.3582？
4.  根据当前实验，能否得出“Dropout 单独使 Test F1 提升了 0.0343”的结论？为什么？

回答：

1.  判断模型效果看的是测试集的表现，训练集和验证集的损失差距只能说明模型再训练集和验证集上效果相当，并不能判断模型好坏
